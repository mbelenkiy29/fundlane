# Workspace setup readiness

`MCA_SETUP_READINESS_ENABLED=true` enables the role-aware setup checklist and administrator diagnostic bundle on the dashboard. Unset or any other value preserves the existing five-step checklist. No migration is required. Readiness is calculated on each read from workspace-scoped company, membership, form, intake, document, sender, funder, billing, deal, and submission records. A saved connection is **configured**; a synthetic intake, ready document, or sandbox submission is **tested**. An accepted teammate, an active billing entitlement, or an existing billing exemption is **live ready** for its respective step. Neither a configured provider nor a synthetic test proves live delivery to a lender or merchant.

Administrators see all seven steps and can explicitly download or copy a JSON diagnostic bundle. Reps and managers see the intake, document, and synthetic deal steps only. The diagnostic endpoint requires an administrator session, returns at most 20 recent local intake/submission IDs with allowlisted states, and excludes error messages, provider payloads, credentials, merchant identity, document content, and bank data. Share the bundle only through the approved support channel. Contextual links point to `/help` articles maintained by the help center.

The flagged dashboard shows a loading message while it fetches setup state. A failed read shows a Retry control without treating the checklist as complete. The regular dashboard refresh also retries it.

## Hosted setup for Michael

1. On an approved nonproduction Vercel preview using a separate Supabase project and synthetic identities, set `MCA_SETUP_READINESS_ENABLED=true`. Keep production unset while reviewing the UI. The feature needs no new OAuth app, callback, inbound mail address, secret, or cron schedule. Existing forms, sender OAuth, billing, document processing, and sandbox setup retain their own activation steps in [application intake](application-intake.md), [background jobs](background-job-runtime.md), [email conversations](email-conversations.md), and [billing](supabase-billing.md).
2. As an admin, set a company name and invite a synthetic teammate. Enable a form in Connections, submit a synthetic application, upload the synthetic statement, and verify the document reaches ready. Verify a sender with a synthetic recipient only after its existing provider setup. Add an active pilot funder without sending to it. Inspect the Stripe test-mode billing status. Enable the sandbox funder, create a deal whose legal name begins `[SYNTHETIC]`, and submit only to the sandbox funder.
3. At desktop and 390px mobile widths, check initial empty/loading, failed connection, retry, configured, and tested states. Download and copy diagnostics as an admin; verify a rep cannot request the diagnostic endpoint. Inspect the JSON before sharing. Confirm no lender or real merchant receives the dry-run submission. Disable the flag to roll back the presentation.

The local tests cover derivation, role filtering, redaction, and database isolation. Hosted Auth, Storage, Stripe test-mode, sender delivery, and browser checks require the approved preview and cannot be claimed from local mocks.
