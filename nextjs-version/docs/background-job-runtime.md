# Background job runtime and cutover map (#35)

## Private email delivery consumer (#39)

`GET /api/cron/private-email` is a separate, opt-in Vercel Node consumer for `application_invitation_email`, `application_invitation_reminder`, and pending intake receipts. `MCA_PRIVATE_EMAIL_CRON_ENABLED=true` enables it; unset or any other value returns `{enabled:false}` without claiming work. Enabled calls require the existing `CRON_SECRET` bearer token, use a 100-second deadline, and process at most three invitation jobs plus three receipts. Invitation delivery also requires `MCA_APPLICATION_INVITATION_EMAIL_ENABLED=true`, `MCA_EMAIL_SENDER_VERIFIED=true`, `MCA_EMAIL_WEBHOOK_URL`, and `MCA_EMAIL_WEBHOOK_TOKEN`; receipts require `MCA_PRIVATE_EMAIL_DELIVERY_ENABLED=true` and a verified sender/receiver or verified useSend integration. Install a single `*/5 * * * *` Vercel schedule only after synthetic hosted acceptance. There is no repository cron entry. The provider receiver must deduplicate delivery IDs because lease recovery alone cannot prevent a duplicate send after a lost response.

This is the source inventory and selected non-Render arrangement as of 2026-09-25. **Current production status for every row below: unverified from source; needs live inventory.** The 2026-09-14 [Render audit](render-deployment.md) recorded failed worker builds, an empty queue, only Stripe Supabase functions, and the Stripe sync cron at that time. It is historical evidence, not a current live inventory. No hosted service was contacted for this change.

## Selected arrangement

Vercel Node owns a gated, bounded `/api/cron/jobs` consumer for private CSV export jobs and opt-in auto-submit scoring. It uses the existing PostgreSQL queue: atomic `FOR UPDATE SKIP LOCKED` claim, ten-minute renewable lease, three attempts, token-fenced completion, and 30-second per-attempt backoff. The route limits each request to three jobs and 240 seconds under its 300-second maximum. `MCA_JOB_RUNTIME=vercel_cron` enables the consumer; unset is an authenticated-free no-op and preserves current behavior. `MCA_AUTO_SUBMIT_ENABLED=true` additionally permits `auto_submit` claims; unset or any other value leaves those jobs queued. `CRON_SECRET` authenticates enabled requests by constant-time bearer comparison. The route has no entry in `vercel.json`: an operator must install exactly one schedule after staging acceptance. The existing `MCA_BACKGROUND_JOBS` setting still controls enqueue versus inline processing; it does not activate this consumer. The export dispatcher cases currently have no in-repository production enqueue call; this route proves the runtime contract with an explicitly enqueued synthetic export, and #37 must connect reviewed export producers before claiming production coverage.

The active data plane remains Supabase Postgres, Auth, and private Storage. Vercel uses restricted pooled `DATABASE_URL`, `MCA_DB_POOL_MAX=2`, and no migration-owner credentials. The queue's unique `(workspace_id,kind,idempotency_key)` and lease token keep job identity stable across a killed execution. A stale worker cannot finish or fail the reclaimed row. Export service operations are idempotent by correlation ID or ready state; CSV results are private and authorized on retrieval. This is at-least-once execution; provider sends require their own receipt deduplication and must not be inferred safe from a database lease alone.

Auto-submit scoring can enqueue a separate `submission_delivery` job; this cron route does not claim that delivery. The original outbound approval is carried into the submission queue, and the legacy worker continues to dispatch `auto_submit` through the same queue. Native scanning/PDF, outbound delivery, and unproven large import/intake tasks are **not** selected by the Vercel claim filter. The existing documents Edge handler still returns 503 before claiming. The native path needs a non-Render container or a measured, resumable equivalent with ClamAV signature updates, Poppler, up to 25 MiB private files, scratch space, scanner verification, heartbeat, and a killed-execution retry proof on nonproduction Supabase. Do not enable an Edge documents schedule or promote unscanned files. `scripts/supabase/deploy.mjs` still gates production Edge deployment.

File/runtime bounds: deal and draft uploads and assistant scans are capped at 25 MiB in source; inbound email is capped at 35 MiB raw payload and 25 MiB decoded attachments. The multipart upload table caps each staged object at 25 MiB. Submission packages, Drive packages, imports and CSV export snapshots have no verified per-job worst-case runtime in source, so do not schedule them on a short function solely because the lease is ten minutes. Invitation and billing work have no file input but depend on provider deadlines; their maximum elapsed time is also unverified. A lease is a recovery deadline, not a process time limit. The Vercel export subset has a 240-second request budget: work stops at 230 seconds and lease cleanup has up to 10 more seconds. Export row processing checks the deadline, and scoped PostgreSQL statements use the remaining time as a server-side statement timeout. An expired export attempt is retried by the queue. Maximum-size staged export acceptance is still required before activation.

## Proof and acceptance boundary

### Assistant maintenance (#45)

`GET /api/cron/assistant` runs on Vercel Node only when `MCA_ASSISTANT_MAINTENANCE_ENABLED=true`; unset or any other value returns an inert response. It requires the existing `CRON_SECRET` bearer credential. A PostgreSQL advisory transaction lock admits one credit/experience/alert processing tick at a time; overlapping ticks return `claimed:false`. Email delivery runs after the locked transaction and uses the existing atomic outbox claim, so no provider request holds the database lock. A 240-second deadline bounds the request under Vercel's 300-second limit. Install a single one-minute schedule after synthetic staging acceptance. Do not add a simultaneous schedule for `scripts/assistant/worker.ts`, and do not schedule a Supabase assistant function. Monitor expired `mca_credit_reservations`, dirty `mca_credit_accounts`, and queued/retry/uncertain `mca_credit_alert_emails`. A local restart/idempotency test uses disposable PostgreSQL; hosted model, Supabase, email, mobile and schedule checks remain for Michael. Disable the flag or remove the schedule to stop consumption. No migration was added.

`tests/jobs-worker.test.ts` uses disposable local PostgreSQL with `MCA_DB_POOL_MAX=2` and synthetic in-memory private storage. It claims a job concurrently, simulates a killed process by expiring its lease, reclaims the **same job ID** with a different token, rejects a stale failure, verifies duplicate-key rejection, delayed retry and the three-attempt terminal state. It also uploads an exact 26,214,400-byte synthetic private PDF, kills the first scan claim, retries it with a mocked scanner, verifies one scan/clean state and the same job ID, and records duration and bytes in test diagnostics. No external message or funder submission is sent. The HTTP tests prove the runtime flag defaults off, missing secret fails closed, wrong bearer is rejected, an authenticated tick completes a synthetic private export, and an auto-submit score-only job remains queued until both runtime and feature flags are on. The legacy worker also completes an auto-submit job. This local proof does **not** prove native binaries or private Supabase Storage behavior on a hosted runtime. Worker credentials are source-checked and locally exercised through `CRON_SECRET` constant-time comparison; staging must verify the restricted role, pooler saturation, and concurrent cron ticks under load.

## Document and intake consumer (#36, code only)

`GET /api/cron/documents` is a separate bounded Vercel Node consumer. Set `MCA_DOCUMENT_JOB_RUNTIME=vercel_cron` to enable it; unset or any other value returns `{ enabled: false }` before database work. Enabled calls require `Authorization: Bearer <CRON_SECRET>` with a timing-safe comparison. Install **one** Vercel cron schedule for this path, every minute, only after synthetic staging acceptance; no schedule is declared in `vercel.json`. Each tick has a 230-second work deadline, processes at most two due attachment retries, schedules at most ten changed intakes, and claims at most two existing `mca_background_jobs`. It writes the existing document worker heartbeat even when idle. The queue's ten-minute lease, renewal, three-attempt limit, token-fenced completion, and idempotency keys remain authoritative. `MCA_BACKGROUND_JOBS=enabled` remains the enqueue control.

The Vercel claim allowlist always includes `draft_extract` (OpenAI API after a clean draft). When `MCA_DOCUMENT_SCANNER=cloudmersive`, it also includes `document_upload`, `document_scan`, `draft_scan`, `assistant_scan`, and `intake_process`; scans in those jobs use the API scanner. ClamAV modes are **never** claimed by this route. Intake processing includes attachment fetch, private document creation, scan, API statement extraction, completeness, and review preparation; a missing scanner or AI provider leaves a visible retryable failure. Attachment retries use the existing attachment lease, integration credential recheck, and workspace scoped document identity. Infected verdicts remain quarantined and are not promoted. `draft_extract` has no automatic producer; a reviewed request must enqueue it. The intake scheduler itself may queue work that waits for the native executor when Cloudmersive is not configured.

The external native executor is the existing `pnpm documents:worker` Node process with `MCA_NATIVE_DOCUMENT_EXECUTOR=true`. Host it in a non-Render container with ClamAV signatures and Poppler, restricted pooled `DATABASE_URL`, Supabase private Storage credentials, `MCA_DATA_ENCRYPTION_KEY`, `MCA_APP_ORIGIN`, and `MCA_DOCUMENT_SCANNER=clamscan` or `clamdscan`. Configure `MCA_DOCUMENT_STORAGE_PROVIDER=supabase`, the private bucket names if overridden, and provider credentials for enabled intake paths. Its authentication is the restricted database role plus private Storage service credential; do not expose an HTTP claim endpoint. It claims only `document_upload`, `document_scan`, `draft_scan`, `assistant_scan`, and `intake_process` from the shared queue using `FOR UPDATE SKIP LOCKED`. It renews each lease every 30 seconds and records a worker heartbeat on every tick. Completion and failure writes must include the lease token; stale results cannot mark a reclaimed job complete. `scanner_unavailable` remains queued for delayed retry until the three-attempt limit, then failed; the document stays unavailable. The native process does not run the attachment/intake schedulers in this mode; the Vercel route owns those. Run exactly one native executor instance unless staging proves concurrent leases and capacity.

At `/admin/status`, the document heartbeat warning names the schedule, credentials, database, and native logs to inspect. The dashboard also counts queued/failed `scanner_unavailable` jobs, with retry guidance. This heartbeat is shared by the cron and native loop, so a fresh value proves a tick ran but does not prove ClamAV health; inspect failed jobs and scan verdicts as well. The monitoring function must be scheduled separately as documented in `platform-status.md` for these values to refresh.

Before enabling the schedule or executor, use an approved nonproduction Supabase project with synthetic records. Deploy the code revision and existing migrations through the reviewed release process; this change has **no new migration**. Configure `CRON_SECRET` only in Vercel and the scheduler, plus `MCA_DOCUMENT_JOB_RUNTIME=vercel_cron`, restricted `DATABASE_URL`, `MCA_DB_POOL_MAX=2`, Supabase URL/service key, private buckets, and `MCA_DOCUMENT_AI_PROVIDER=openai`, `MCA_DOCUMENT_AI_MODEL`, `OPENAI_API_KEY` if extraction is enabled. For API scanning configure `MCA_DOCUMENT_SCANNER=cloudmersive` and `MCA_CLOUDMERSIVE_API_KEY` from the Cloudmersive console; for ClamAV keep scanning on the native executor. Verify the scanner's provider console key and egress policy, and test the EICAR fixture before enabling a production schedule. No OAuth app or callback URL is required for this consumer. Confirm 25 MiB upload, clean promotion, malware refusal, killed claim and restart, duplicate delivery, late statement, revoked integration, cross-workspace isolation, fresh heartbeat, and sanitized job IDs in staging. Production activation and revision evidence require Michael's hosted access. Roll back by unsetting `MCA_DOCUMENT_JOB_RUNTIME` and stopping the native executor; keep queued jobs and quarantined objects for review.

Ownership of the original kinds after this code change: `document_upload`, `document_scan`, `draft_scan`, `assistant_scan`, and `intake_process` have the gated Vercel API-scanner path or the native executor. `draft_extract` has the gated Vercel path. Attachment retries and intake polling have the cron scheduler. `email_intake`, `intake_replay`, `multipart_task`, `drive_preview`, `drive_apply`, `import_commit`, and `import_update_commit` remain on the legacy dispatcher pending resource/runtime bounds from #35 and require separate follow-up before Render retirement. `submission_delivery` and invitation kinds remain separate outbound work; `export`/`export_create` and `auto_submit` belong to `/api/cron/jobs`; billing has its own cron. No job kind was silently reassigned to this consumer.
